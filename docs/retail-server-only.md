# Retail — واجهة واحدة متصلة بالخادم

أصبحت الواجهة الفعالة تتطلب تسجيل الدخول إلى Backend. أُزيل زر التجربة المحلية ومسار التطبيق المحلي وملفات الحالة والتخزين والبيانات التجريبية التابعة له. بقيت مكونات التصميم المشتركة، وتوجه مداخل الشاشات القديمة الآن إلى شاشات الخادم.

احتُفظ بالهيكل والألوان والقوائم والكاشير والمنتجات ونوافذ اختيار المنتج والباركود. نُقل تنسيق جداول العملاء والفواتير وأزرار التعديل والتفاصيل والطباعة والدفعات إلى الوظائف الموجودة في الخادم. أُضيفت حقول بيانات العميل الوصفية إلى نموذج الخادم. اختصارات الشركات والمرتجعات والباركود تستخدم الآن فلاتر وطلبات الخادم؛ البحث عن ملصقات المنتجات لا يقتصر على الصفحة الأولى.

لم تُنقل بيانات LocalStorage القديمة. تبقى تفضيلات العرض وهوية الجهاز وآلية استرداد الكاشير اللازمة للخادم؛ لا تمثل تطبيقًا محليًا منفصلًا. لم تُنقل أي وظيفة مالية محلية تتجاوز صلاحيات الخادم أو التفعيل أو آلية تثبيت المستندات.

## الحفاظ على البيانات وإمكانية التراجع

لم تُنفذ مهاجرات أو عمليات بيع أو مشتريات أو تعديل بيانات تجارية ضمن هذا التغيير. قاعدة Developer هي sham_retail_dev على المنفذ 5432. التعديلات الخلفية مقتصرة على فلاتر قراءة للجداول مع الاحتفاظ بنطاق الشركة والصلاحيات والتحقق من المدخلات.

حُفظت نسخة مصدر الملفات المعتزلة فقط مع بصماتها في .developer/source-retirement قبل إزالتها من المصدر الفعال. ليست تطبيقًا ثانيًا منشورًا. لا تحذف مجلد .developer؛ يحتوي أيضًا إعداد الاتصال والتفعيل. لم يُعدّل pos-offline أو خدمات Windows أو إعداد نشر الإنتاج.

## التحقق

اختبارات server-only.browser.mjs تتحقق من الدخول الإلزامي وتجاهل بيانات المتصفح القديمة وفتح الأزرار والفلاتر والباركود، مع منع كتابة البيانات التجارية ومقارنة عدد السجلات قبل الاختبار وبعده. تُعرض فاتورة وهمية عبر اعتراض GET داخل متصفح الاختبار فقط لاختبار أزرار الجدول دون إدراج فاتورة في القاعدة. اختبارات appearance.browser.mjs تتحقق من الألوان والوضع الداكن والهاتف والاتجاه والشاشات المتصلة، وتمنع الكتابات التجارية أيضًا.

الفتح: http://127.0.0.1:5196/inventory
التشغيل: npm run dev
الإيقاف: npm run dev:stop
عرض بيانات تسجيل الدخول محليًا: npm run dev:login
